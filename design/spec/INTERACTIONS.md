# 화면 구현과 상태 규격

기준: 1440×900, 콘텐츠 x=164…1392. 주차 및 UX 허용 상태에서만 게임 입력을 받습니다. 모든 수량과 조건은 실행 직전 저장소 트랜잭션에서 다시 확인합니다.

## 10 식물 상세

씨앗/새싹: 현재 이름, 단계, 누적 XP/다음 임계치, 다음 단계까지 필요한 XP, **현재 단계**의 3특성 점수, 다음 단계 예상 이름을 표시합니다. 점수는 백분율 대신 정수 ‘점’으로 표시하며 막대는 비교 보조입니다. 세 막대는 같은 눈금을 사용합니다. 상한은 세 점수(미리보기 포함)의 최댓값을 10점 단위로 올림한 값, 최소 10점입니다(예: 최댓값 14점이면 상한 20). 전부 0점이면 빈 막대입니다. 막대가 가득 차도 성장 조건을 충족했다는 뜻이 아닙니다.

주 행동은 **특성 가꾸기 → 12**, 보조 행동은 **동반자 선택 → 05**. 씨앗도 동일한 배치이며 다음 단계는 새싹입니다. 새싹의 현재 앞말과 다음 성체의 예상 앞말은 다를 수 있습니다.

성체: 누적 XP, 확정 이름, “성체의 이름 앞말은 이제 바뀌지 않아요”와 동반자 선택만 표시합니다. 초기화된 0점 막대나 재료 버튼을 남기지 않습니다. 현재 동반자라는 배지는 실제 준비/활성 여정에 속할 때만 표시하며 예시 화면에는 넣지 않았습니다.

## 11 말랑 심기 확인

진입: 14의 심기, 09의 심을 화분 고르기, 홈 빈 슬롯. 기본 선택은 가장 낮은 번호의 빈 화분; 홈 빈 슬롯으로 들어오면 그 슬롯을 우선합니다. 사용 중 슬롯은 비활성으로 만들고 식물 교체/삭제를 제안하지 않습니다.

확정 버튼은 `{번호} 화분에 심기`. 말랑 1개 감소, 선택한 슬롯에 SEED 식물 1개 생성. 재료 차감 없음. 성공 후 정원으로 돌아가 해당 화분을 강조하고 “{종} 말랑을 심었어요”를 알립니다. 확인 전에는 어떤 자원도 쓰지 않습니다.

- 빈 화분 없음: 11b. 확인 비활성, 가방으로 버튼.
- 말랑 재고 0: “이 말랑은 가방에 없어요”, 확인 비활성, 가방으로.
- 실행 중 슬롯 점유/재고 변경: 갱신한 상태를 보여 주고 “화분이나 가방 상태가 바뀌었어요. 다시 선택해 주세요.” 다른 빈 슬롯에 자동으로 심지 않습니다.
- 저장 중: 버튼 로딩, 중복 입력 금지. 성공 이벤트를 소비하고 화면을 닫습니다. 단순 버튼 연타가 말랑 2개를 소비하지 않도록 operation 상태를 유지합니다.
- 실패: 선택을 유지하고 재시도; 저장 성공 여부가 불명확하면 먼저 DB를 재조회합니다.
- 뒤로/닫기: 아무것도 소비하지 않고 원래 화면으로.

## 12 특성 가꾸기

입력: plantId, 현재 단계/XP/점수, 보유 재료. 처음에는 보유한 재료 중 콘텐츠 순서상 첫 항목과 수량 1을 선택합니다. 화면 예시는 사용자가 바람돌을 선택한 상태입니다. 재료가 전부 없으면 미선택/수량 0으로 표시합니다.

재료를 고르거나 수량을 바꾸면 **메모리상** 미리보기만 계산합니다. 바뀐 점수는 `before → after점`, 예상 이름은 엔진 `prefixFor`의 동일한 동점 규칙으로 계산합니다. CTA는 `{재료명} {수량}개 주기`. 수량 범위 1…보유수량, ± 버튼 64×64. 하한에서 −, 상한에서 + 비활성.

예시: 새싹 37 XP, 물가12/산자락9/도시1. 바람돌1개를 주면 12/14/1, 예상 성체 이름은 산자락의 달빛종. 현재 이름 ‘물가의 달빛종 새싹’과 37 XP는 바뀌지 않습니다. 점수 때문에 성장 애니메이션을 재생하지 않습니다.

- 사용 성공: 10으로 돌아가 실제 새 점수를 보여 주고 “산자락 특성 +5점 · 바람돌 1개 사용” 알림. 예상 이름을 확정된 이름처럼 알리지 않습니다.
- 재료 부족: 해당 항목 `보유 0개`, 수량/확정 비활성. 다른 재료는 선택 가능.
- 사용해도 예상 이름이 같음: 사용 가능, “아직 예상 이름은 같아요. {특성} 점수가 높아져요.” 보조 설명.
- 양수 동점: “같은 점수면 물가 → 산자락 → 도시 순서로 정해져요.”
- 전부 0점: 앞말 없는 다음 단계 이름과 “아직 지역 특성 점수가 없어요.”
- 화면 밖 정산으로 성체가 됨: 입력 중단, 재고 차감하지 않고 “이미 성체로 자랐어요. 이름이 정해졌어요.” → 10b.
- 새싹으로 단계가 바뀌었지만 성체 아님: 이전 단계 미리보기를 버리고 새 점수로 재계산. 사용자가 다시 확인해야 하며 자동 실행 금지.
- 저장 중 중복 입력 차단, 에러 시 DB 재조회 후 재시도. 재료 사용은 현재 Repository에서 요청 ID 멱등성을 제공하지 않으므로 재개 시 자동 재전송하지 않습니다.

## 14a 재료 설명 시트

가방 위 오른쪽 시트: 이름, 보유수량, 연결 특성 배지, 1개당 +5점, 씨앗/새싹만 가능, XP/원화 불변 설명. 시안은 바람돌이며 달빛이슬/구름빛은 같은 구성에서 아이콘·특성·이름만 바꿉니다. 읽기 전용; “확인”과 우상단 닫기는 동일하게 시트를 닫습니다. 가방 뒤 목록의 스크롤과 탭을 유지합니다. 아래 화면의 터치와 접근성 포커스는 막습니다.

## 15 / 15a 도감

도감 항목 키는 speciesId이며 슬롯 번호가 아닙니다. 카드 탭 콜백은 `onOpenSpecies(speciesId)`로 바꿉니다. 미발견은 이동하지 않습니다. 가장 많이 자란 개체의 단계·XP를 보여 주되 제목은 종 이름입니다.

15a는 성장 모습을 설명하는 읽기 전용 화면입니다. 대표 개체의 단계까지의 그림은 정상 표시, 아직 이르지 않은 단계는 흐린 실루엣과 잠금으로 표시합니다. 시안은 성체까지 자란 경우입니다. 같은 종을 여러 개 키울 때는 앞말이 다른 개체가 있어도 대표 개체만 아래 요약에 보여 줍니다. 심기·재료 사용·동반자 선택 버튼을 여기에서 제공하지 않습니다.

## 05 → 06 → 08 → 09 여정 인계

### 05 / 06: 준비와 출발은 구분

05는 1~3개 선택 후 “이 식물들과 함께”로 준비 상태를 저장하고 06으로 갑니다. 0개일 때 CTA 비활성, 3개일 때 미선택 카드의 추가 선택 비활성(선택 해제는 가능). 성체/말랑도 동반자 가능. 이미 활성 여정이 있으면 출발 시 확정한 동반자를 바꾸지 않습니다.

06은 **출발 대기 화면**입니다. 정차 중에는 동반자 바꾸기가 가능하며 아직 거리 정산용 ACTIVE 여정을 만들지 않습니다. 실제 차량 신호로 출발 이벤트가 생길 때 준비된 ID와 시작 Odometer를 고정하고 `startJourney`를 한 번 호출합니다. UX 차단 자체와 이동 시작 조건은 T08/T09에서 분리하십시오. D에서 멈춰 있어도 화면 차단은 즉시 적용됩니다. 차단 이벤트만으로 이미 활성인 여정을 다시 만들면 안 됩니다.

현재 Repository의 `startJourney`는 바로 ACTIVE를 만듭니다. 따라서 **05 완료 시 곧바로 startJourney를 부르는 방식은 자동 출발 설계와 다릅니다.** ReadySelection 저장/복구 상태와 차량 이벤트 조정기가 추가로 필요합니다. 앱 재시작 시 기존 ACTIVE 여정이 우선합니다.

주차 복귀/도착 조건을 만족하면 끝 Odometer와 도착 지역으로 정산합니다. UX 허용 재진입만으로 정산이 중복 생성되지 않게 하고 기존 journeyId를 재사용합니다. 출발/도착 debounce와 실제 신호 조합은 API_FACTS에 맞춰 구현·실차 검증합니다. UI 시안은 그 동작이 이미 구현됐다는 뜻이 아닙니다.

### 08: 결과는 저장된 정산을 읽기

지역 배지, 도착 지역, 유효 거리, **개체별 실제 xpGained**, 실제 단계 변화와 지역 보상을 표시합니다. 일일 상한이 다르면 “모두 +10 XP” 같은 공통 문구를 쓰지 말고 카드별로 표시합니다. 성체에는 특성 +점 문구가 없습니다. 성장이 일어나면 저장된 전후 단계를 기준으로 13을 보여 주고 결과로 돌아옵니다.

보상 지급은 settleJourney가 끝날 때 이미 완료됩니다. “말랑 만나기”나 뒤로가기는 지급 트리거가 아닙니다. `alreadySettled=true`이면 저장 결과를 보여 주며 새 지급/추첨/도감 해금을 하지 않습니다. 화면 재진입마다 전체 성장/획득 연출이 재생되지 않도록 journeyId별 확인 상태를 둡니다.

### 09 / 13

09는 보상이 저장된 뒤 말랑의 종류를 보여 줍니다. `심을 화분 고르기 → 11`, `나중에 심기 → 정원`. 뒤로가면 08이며 이미 받은 말랑은 가방에 남습니다. 빈 화분이 없으면 심기 CTA 비활성과 “빈 화분이 생기면 심을 수 있어요”; 정원으로 돌아가는 행동은 유지합니다. 말랑 보상이 없으면 09를 건너뜁니다. 원화와 이름은 결과의 seed 값에서 가져옵니다.

13은 자동 성장 확인입니다. 진화 선택, 재료 소비, 별빛형 변경은 없습니다. 여러 개체가 성장하면 순서대로 표시하되 건너뛰기로 전체 결과를 볼 수 있게 합니다. SEED→MATURE 두 단계를 한 번에 통과한 경우 엔진에서 결정한 최종 이름/원화를 표시하고 “말랑 → 성체”로 씁니다.

### 결과 예외와 데이터 부족

| 조건 | UI / 동작 |
|---|---|
| Pending | “거리 확인 중” 상태, 보상 카드/0 km 확정 표시 없음. 저장된 동일 journeyId로 재조회 |
| 시작 값 없음 | 뒤늦은 현재 Odometer를 과거 출발 값으로 대체하지 않음. 출발 당시 스냅샷 복구 또는 명시적 복구 정책 필요 |
| Rejected | “이번 여정의 거리를 확인할 수 없었어요” / 성장·보상 없음 / 정원으로. 음수 거리 표시 금지 |
| 정상 0 km | 0.0 km, 개체별 +0 XP. 지역 보상 존재 여부는 실제 정산 결과대로 표시 |
| 도착 지역 unknown | 유효 거리 XP 정상, “도착 지역 미확인”; 특성/지역 보상 없음 |
| 지원 지역 밖 | “지원 지역 밖”; 나머지는 unknown과 동일 |
| 같은 지역 당일 재방문 | 지역 보상 없지만 실제 XP/특성 증가는 정상 표시. 말랑 발견 화면 생략 |
| 일일 XP 상한 | 개체 카드에 실제 +0/+잔여 XP, “오늘의 거리 경험치를 모두 받았어요” |
| 말랑 추첨 없음 | 재료만 결과에 표시. 발견 CTA 대신 “정원으로” |

현재 `SettlementView`에는 arrivalRegion, 특성 점수 변화량, 전후 이름, seen 상태가 없습니다. 필요하면 여정/성장 스냅샷으로 ViewModel 표시 모델을 확장하세요. 보상이 없다는 이유만으로 지역 unknown을 추정하지 마십시오(당일 재방문도 보상이 없음). 재현 시 현재 개체 이름을 과거 여정의 성장 결과로 표시하면 기록이 달라질 수 있습니다. 전후 이름을 안정적으로 저장하기 전에는 08에 종 이름+전후 단계+xpGained만 표시하고, 확정 앞말 연출은 생략하는 축소 구현이 가능합니다.

## 내비게이션·접근성

- 상세 뒤로가기 x164,y114,w64,h64. 제목 x248. 시스템 뒤로가기에 의존하지 않습니다. 버튼 라벨은 “뒤로, {복귀 화면명}”. 스크롤해도 상단 고정.
- 시트 닫기 x1328,y48,w64,h64. 클릭 영역 64, 시각 아이콘 24. 시스템 back 이벤트가 있으면 같은 동작에 연결.
- 복귀 대상은 실제 진입 경로를 보존합니다. 11 취소는 가방/09/홈 중 호출자, 12는10,15a는15. 05/06은 정원 탭을 선택 상태로 유지합니다. 08/09/13은 여정 탭입니다.
- 화면 전환은 180~220ms, 재료 성공 알림은 약 3초와 접근성 announce. 제한/움직임 줄이기 시 연출 생략. 필수 정보는 알림에만 두지 않습니다.
- 배지 텍스트와 숫자로 의미를 중복 제공. 색만으로 선택/성장/잠금을 표현하지 않습니다. 아이콘은 인접 텍스트가 있으면 장식 처리해 중복 읽기를 피합니다.
